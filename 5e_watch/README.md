# 5e_watch — внешняя проверка платформы 5Э

Запускается в GitHub Actions каждые 5 минут, вне серверов платформы, и смотрит
то, что видит пользователь:

- имена разрешаются через Cloudflare и Google DNS-over-HTTPS;
- HTTPS по имени отдаёт ожидаемый код (`5espace.com` — 200, `files.5espace.com` — 404);
- если имя не разрешается — то же по IP с правильными Host и SNI, чтобы
  различать «DNS не отвечает, сервер жив» и «сервер не отвечает»;
- срок сертификата и регистрации домена;
- пульс (если задана переменная `FIVE_E_PULSE_URL`): ответ 200, `ok === true`,
  корректное и свежее время.

Тревоги — в Telegram при смене состояния и напоминанием раз в час. Запуск
краснеет (и GitHub шлёт письмо), только если тревога не дошла до Telegram. Токен бота и
ID чата — только в GitHub Secrets (`FIVE_E_TELEGRAM_BOT_TOKEN`,
`FIVE_E_TELEGRAM_CHAT_ID`).

**Что значит цвет запуска.** Зелёный — проверка выполнена и нужные
уведомления доставлены; это НЕ «платформа исправна»: о проблемах платформы
говорит Telegram. Красный — тревога не дошла до Telegram (тогда GitHub
присылает письмо о провале — запасной канал).

**Учения** — ручной запуск с параметром `drill`: `fail` — учебная проблема,
`ok` — её снятие (сообщение о восстановлении), `undeliverable` — учебная
проблема с неверным токеном (проверка письма GitHub). Рабочий сайт и рабочее
состояние тревог не затрагиваются; сообщения помечены «[УЧЕНИЯ]».

Ограничения: расписание GitHub может задерживаться и пропускать запуски;
остановку самого расписания эта схема не обнаруживает. Временная мера.

Проверки: `node --test 5e_watch/external-check.test.mjs`.
